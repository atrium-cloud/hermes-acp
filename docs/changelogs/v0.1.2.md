Requires Hermes Agent 0.21.3 (`v2026.9.14`) or above. That release replaced the `approval.request`/`clarify.request` events and their `*.respond` methods with JSON-RPC server-to-client requests; on older Hermes builds approvals and clarify questions never reach this adapter, so the supported floor moves from 0.20.6 to 0.21.3.

## Approvals and clarify on the 0.21.3 wire

- The `approval` server request maps to `session/request_permission` and is answered with a response frame on the same request id. Fail-closed behavior is unchanged: an unanswered, stale, or idle-session approval resolves to `deny` exactly once.
- The `clarify` server request maps to `elicitation/create` and is never auto-answered; Hermes' own timeout resolves it.
- `request.cancel` from the gateway withdraws the pending client-side permission or elicitation card.
- Server requests with no ACP counterpart (`sudo`, `secret`, `terminal.read`, `preview.*`, `window.read`, `tour`, `mcp.setup`, vault prompts) are refused with JSON-RPC method-not-found, so the tool fails immediately instead of waiting out a bounded timeout.
- Known limit: requests left open by a previous client are not re-delivered on `session/resume` (docs/caveats.md).

## Terminal tool calls render as ACP terminal entries

- A Hermes `terminal` tool call now carries a `terminal` content block plus `_meta.terminal_info`, `_meta.terminal_output`, and `_meta.terminal_exit` (the Zed convention pi-acp and claude-agent-acp use). The terminal id equals the tool call id; `cwd` is the call's `workdir` argument or the session cwd.
- The command's output and exit code reach the client on every run, not only in verbose tool-progress mode. Output arrives in one frame at completion, as the gateway emits no mid-run output events.
- `exit_code` is `-1` for an executor error, `124` for a timeout, and null when the command yielded to background; `terminal_exit` is omitted when the result did not decode.
- Replayed history rows from `session/load` stay plain tool calls, and the `process` tool keeps the plain execute rendering.

## Development

- `bun run drift` now diffs consumed server-request names as well as methods and events, and follows the new upstream method registrars.
- `bun run test:e2e:sprite` runs the live e2e tier in an ephemeral Fly.io sprite against the pinned Hermes and saves scrubbed evidence under `e2e-evidence/`. Verified against live Hermes 0.21.3 on 2026-09-21, including the terminal-entry case.
